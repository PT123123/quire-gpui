# 验收与证据要求

所有数值是复刻验收的建议门槛，开始实现时按旧版同机测量确认并记录；不是 GPUI 性能承诺。建立 `validation/`：环境说明、参考图/新图、diff、交互记录、测试输出、性能原始数据和问题列表。

## 参考采集

记录旧版完整 commit、工作树 dirty、core rev、renderer、构建 profile、OS、GPU、驱动、窗口逻辑/物理尺寸、DPI、字体和数据种子。新旧在同条件采集；图片按 theme/size/dpi/scene 命名。

旧版现有工具示例：`quire-shot --out <test-output.bmp> --scene <实际场景> --w 1280 --h 800 --theme jade`。使用现有支持 software 的构建，具体命令核对旧版 justfile。

**数据边界（2026-10-14 读源码更正）**：`quire-shot` 只在场景名包含 `backlinks` 或 `database` 时开库，且开的是 `SqliteRepository::in_memory()`（`src/bin/quire_shot.rs:369-380`），其余场景 `repo = None` 走内存 demo 会话。它**不接收 `--db`，不读写任何库文件**，因此本工具可安全重复采集；早前"场景会创建真实测试数据"的说法针对的是带 `--db` 的正常启动，不适用于此。仍要注意：无头进程会尝试绑定同步端口 5878/5879，被占用时打印 `os error 10048` 后继续渲染。

**单位坑**：`quire-shot` 用 `PhysicalSize::new(w, h)` 设定尺寸，所以 `--w 1280` 是 **1280 物理像素**，与系统缩放无关。这类离屏图不能充当 DPI 缩放验收证据；125%/150%/200% 必须在真窗口上测。

已完成的基线采集与它读出的事实（含 4 组重复哈希的含义、未覆盖清单）见 `docs/14-REFERENCE-SHOTS.md`；场景名清单见 `docs/15-SCENE-CATALOG.md`，采集脚本 `tools/capture-reference-shots.ps1` 内置了「场景名打错会静默渲染默认页」的 NO-EFFECT 检查。

旧版 software 截图与新 GPUI GPU 字体栅格不同，可用于布局和 token 参考；重要体验还需同机旧版默认 FemtoVG 真窗截图比较。不能要求两个不同 rasterizer 全图像素差为零。

## 视觉矩阵

- 1280×800、窄窗口约 900×700、1920×1080；窗口最小尺寸按旧版限制补测。
- 100%/125%/150%/200% DPI；记录尺寸单位，避免把逻辑 1280 与物理 1280 混比。
- 全部 12 theme + system 明/暗；四个渐变全页、scroll、resize、多窗口。
- 主壳、空页、长文档、全块、封面、图标、页菜单、slash、marks、搜索/命令/查找、版本历史。
- 数据库全部视图与配置弹层；笔记/任务/详情/多选/标签/撤销条；设置所有入口；同步/MCP 状态；速记。
- hover/pressed/focus/disabled、长标题、无结果、失败提示、模态与锚定弹层。

建议关键几何偏差≤2 逻辑像素、字号/token 数值一致；纯色大区域每通道偏差≤2/255（排除边缘、透明合成和截图色彩管理差异）；渐变采样与参考一致、方向/连续性无误。文本抗锯齿单独 mask，不能 mask 掉文本区域来掩盖错误字体/行高。

验收看 diff 和并排图，检查换行位置、baseline、颜色、面板边界和命中区域。全图相似度只作辅助，不作为“完美复刻”的唯一结论。记录每项例外和原因。

## 动效

主题切换、侧栏折叠、hover/pressed、菜单等逐项核对时长/easing。采集起始、中间、结束帧，证明真实插值而非终态截图；动画停止后观察刷新/CPU。保留交互期间滚动和点击可用性。

## 编辑与交互

真实 OS 中文输入测试不可由合成文本替代。按 docs/05-EDITOR 案例执行；另测鼠标选择、拖动落点、菜单边界、Escape 层级、焦点恢复、Tab 顺序、速记/主窗切换。

有意义的自动化覆盖：输入→core 命令/undo 的正确性、UTF 位置转换、composition 状态、selection geometry、可变高滚动锚点、异步旧结果丢弃、批量撤销、保存失败保留。不要只测试函数返回自己刚写进去的常量。

## 数据

测试库创建→编辑→保存→退出→重开→旧版读取，比较语义内容/ID/marks/树/属性/附件哈希。测试失败提交、崩溃重启、只读、损坏库恢复、未知设置、延迟删除超时/撤销、MCP 写后 UI 刷新。

同步使用独立测试库/设备，验证双向增删改、冲突、断连和协议拒绝。保留状态日志，但脱敏路径与设备信息。

## 性能

同机 release 构建重复测：空壳、1000 块、10000 块、连续滚动、100 页切换、10000 块里持续输入、数据库大表、整理区大列表。记录启动到首帧/可输入、Working Set、Private Bytes、CPU（说明按一核或整机）、输入到显示延迟和帧时间 p50/p95/p99。

旧版 README 的 0.1.26 示例：10000 块 Working Set 约 124.1MB/Private 95.2MB，空壳约 107.8/79.1MB；具体同机当前值优先，不把历史值直接当硬门槛。建议新实现关键场景内存不比同条件基线多 20%以上、静止无焦点 CPU 接近 0（目标低于一核 1%）；输入/滚动 p95 不退化，原因和例外单独讨论。

性能未实测就不能写“GPUI 更快、更省内存”。截图能生成也不能证明渲染帧率、输入延迟或候选框正确。

## 最终门槛

功能矩阵所有范围内项已验证；严重问题（丢输入/数据损坏/IME 不可用/核心入口不可达）为零；12 主题和 4 渐变通过；Windows 多窗口/热键/托盘通过；兼容往返和同步通过；差异完整披露；候选包可安装和卸载。未测真机 IME、未测同步或只完成主壳时，不能称完整复刻。
