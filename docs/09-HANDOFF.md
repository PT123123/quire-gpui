# 给实现 AI 的直接任务

你要在 quire-gpui 中实现 Quire 的 GPUI 桌面版。用户要求尽量完美复刻现有 quire-desktop，包括所有界面和渐变主题。这里已有详细规格和冻结参考源码，没有 GPUI 实现，不要误报完成。

## 第一轮应做什么

1. 读 AGENTS.md、PLAN.md、本 docs 全套，**外加 `docs/13-DECISIONS-NEEDED.md`（2026-10-14 已拍板一轮，看开头的拍板表；标"已定"的不得回退成建议）和 `docs/ADR-001-GPUI-STACK.md`（已核验的上游事实与 7 条探针）**。
2. 读 `docs/11-CORE-API.md` 再读旧版 `ui/Types.slint`、`ui/AppWindow.slint`、`EditorBlock.slint`、`state.rs`、`controller.rs`。功能清单以 `docs/PARITY.csv` 为骨架（246 callback / 261 property / 188 场景），逐行补语义列，不要另起一套编号。
3. 先跑 ADR-001 第 6 节的 7 条探针（最小窗口、微软拼音、富文本折行、根级渐变、万条虚拟列表、无边框+Snap、托盘与热键），把实测结果写回该文件；在此之前不要写任何界面代码，也不要相信任何按 crates.io `gpui 0.2.2` 写的示例。官方 gpui 与 gpui-kit **都允许评估**，用输入效果、维护成本、组件能力三项比较后定栈。
4. 创建独立 Rust 应用，在测试库上打通加载/保存和最小块编辑器——这一步就是 AGENTS.md 的**「第一竖切」：能运行 + 能用微软拼音输入 + 能保存一页并重启读回**。三项缺一就不算交付，不要靠多加页面、主题或整理区来撑场面。
5. 第一竖切过了再展开 P1 其余闸门（选区、折行、undo、虚拟化），然后 P2–P7。视觉对照基线用 `reference/shots/`（312 张，含 manifest 与哈希，已冻结为 `baseline-2026-10-14`）。

## 用户最在意什么

视觉一致性必须认真做，不能交付默认组件库主题的“类似应用”。12 主题不是 2 主题；四种渐变不是把整个编辑区填一个近似深色。页面/整理区/设置/数据库/速记要一起对齐。图标、排版、紧凑程度、交互入口与中间状态也算复刻。

编辑体验是改用 GPUI 的核心理由，但不能宣称框架天然解决所有问题。必须证明真实中文输入、富文本折行和焦点行为。修复旧版明确平台限制可以，功能删减或布局重设计不可以默认进行。

## 容易踩的坑

- 旧版当前工作区包含未提交修改，仅用 Git HEAD 会漏掉 MCP 和退出等最新改动。
- 原 docs 是历史累计，早期“未来支持”可能已实现；必须查源码。
- color 8 位值 RRGGBBAA，渐变角度需适配，mix 需核实。gpui 的 `linear_gradient` 插值取自绘制四边形自身包围盒，"整窗一条连续 ramp"要靠根元素铺满窗口（ADR-001 第 3 节）。
- 主题在窗口根部连续铺设，不能每块重启或随 scroll 移动。
- 旧版单输入策略不是要求 GPUI 继续编辑时退化为无格式文本。
- **文本单位已确定：core 全部用 UTF-8 字节偏移**（`core/types.rs:407-408` 等四处证据），转换只准发生在适配层一处。
- **块类型的 0..24 数字是桌面端自造的 Slint 菜单 id**（`state.rs:5974`），core 存的是字符串；反过来 `ColorKind::slot`、`PropertyKind::index`、`ViewLayout::index`、`FilterOp::index`、`highlight::Kind::from_int` 是承重数字，不许重排。
- **撤销栈在 core**（每页 CAP=100，整理区共用 `ORGANIZER_STACK`），新组件自带的 undo 不能同时生效。
- UIState 回调不能原样当作 core API；稳定 ID 不能变成行索引（core 的 ID 全是 `u64` newtype）。
- 246 个 callback 里有 14 个只有声明没有调用点（`docs/PARITY-UNWIRED.txt`），它们对应的行为改走了 property（草稿）或 `changed` 回调（弹层关闭）——**不要照名字写 14 个空处理器**，要复刻的是行为。
- 同步/MCP 的 Job 泵、设备 ID 持久化、`MergeCtx` 的 10 个 ID 分配闭包都在壳侧，core 帮不了；gpui 没有托盘能力，那部分从旧版 `src/platform/` 移植。
- `quire-shot` 用内存库、可安全重复采集，但它对无法识别的场景名**静默渲染默认页**；4 个 motion 名（`sidebar-toggle`/`theme-fade`/`mcp-toggle`/`board-drag`）不是静态场景。
- 整理区右侧导航、多选独立 ID、延迟删除、独立撤销栈和速记共享草稿容易被遗漏。
- 同步和 MCP 属于当前产品，不是可随意砍掉的扩展。

## 每轮输出

交付可运行结果、更新矩阵/计划、给出可复制启动和验证命令，说明已实现/已验证/未验证。保留数据安全，不覆盖旧版库或安装。发生关键阻塞说明具体复现、尝试、官方依据和下一步，不以“GPUI 限制”一句话结案。

## 用户可复制的任务提示

> 请在此目录按 AGENTS.md 和 PLAN.md 完成 Quire GPUI 桌面复刻。先阅读 docs/01–09 及 reference 快照。复用旧版锁定的 quire-core，逐项对齐全部页面、编辑/数据库/整理/同步/MCP/桌面功能；严格保留 12 套主题和 4 套窗口级渐变、字体、图标、间距、动画。先通过真实 Windows 中文输入、富文本折行、选区、撤销和万块虚拟化验证，再完成其余界面。用独立测试库，不修改旧版和 Android，不写真实用户数据。每阶段更新功能矩阵和验证记录，未验证项明确标出，达到完整复刻验收后交付候选安装包与回退说明。
