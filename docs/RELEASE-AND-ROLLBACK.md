# GPUI 候选版安装、切换与回退

本文面向候选版验收，不授权自动迁移或使用真实用户库。Slint 旧版继续保留；GPUI 使用独立安装标识和 `%LOCALAPPDATA%\QuireGPUI\quire.db`。两版不能同时打开同一个数据库写入。

## 候选包验收

1. 仅从锁定依赖构建 Release，并记录源码 commit、Rust/Cargo 版本、构建命令、耗时和最终二进制 SHA-256。最终性能比较另按 `PLAN.md` 的 P7 项目执行；功能冻结前记录的单次构建耗时不作为两版结论。
2. 运行全量自动测试、隔离 Release GUI smoke、旧版同库兼容和同步线协议回归。所有测试必须使用新建的 `%TEMP%` fixture 或 `quire-gpui` 仓库下的自动化测试库。
3. 生成便携 ZIP；安装器仅在 Inno Setup 6 编译器可用时构建。将 ZIP 解压到全新临时目录，核对包内 EXE SHA-256 与构建产物一致，再启动并退出。
4. 记录未通过、未覆盖和必须由真实桌面操作验证的项目。人工门（IME、托盘、多屏、DPI、鼠标命中）未通过前，不称为完整验收版。

## 切换前备份

- 先完全退出 Slint 和 GPUI，检查任务管理器确认没有仍在运行的 Quire 进程；不得在两版同时运行时复制或切换同一个库。
- 在旧版中确认当前库路径并使用旧版已有备份功能；另将旧版数据库所在的**整个数据目录**复制到带日期的离线备份位置。保留数据库、SQLite sidecar、附件目录、页面版本与配置文件，不能只复制 `.db`。
- GPUI 第一次正式评估时使用它自己的 `%LOCALAPPDATA%\QuireGPUI\` 空目录。若需检查旧数据兼容，先退出旧版，再把完整副本放进 `%TEMP%`，用 `--db` 显式指向副本。绝不对旧版原库执行此步骤。
- 记录源目录、库文件大小、页面/块/数据库/笔记/任务数量和附件哈希清单；成功打开、保存、关闭并重开后复核这些值。使用中的真实库当前不在本轮授权范围内。

## 回退

- 候选评估期间，旧版原安装与原数据目录保持原样。遇到 GPUI 问题时退出 GPUI，重新启动旧版并选择旧版原库；不需要把 GPUI 试验库合并回旧版。
- 若 GPUI 试验库需要重置，退出 GPUI 后移走整个 `QuireGPUI` 试验目录，再从切换前副本恢复整个目录；不要在运行中的库上替换单个数据库文件。
- 只有当全量旧版→GPUI→旧版往返覆盖到用户实际使用的数据类型后，才可讨论迁移。此时先制作并验证备份副本，在副本上完成双向往返，再单独安排真实迁移；保留源库直到用户确认回退窗口结束。
- 卸载 GPUI 不会删除 `%LOCALAPPDATA%\QuireGPUI`，也不应卸载 Slint。卸载后的数据清理需在用户确认后手动进行。

## 当前状态与发布门

已验证 GPUI 的隔离 SQLite 启动备份、活动会话周期快照与损坏恢复、旧版基本/复杂数据库同库往返、v4 同步线协议中的 Number/Formula/Select/Relation/Mirror/Rollup schema、两个方向的同步附件二进制往返、双节点 loopback 上文件列引用移除与恢复，以及便携 ZIP 结构和临时解压启动。周期备份失败会在 UI 明确说明主库保存状态并提供手动重试入口。附件实体回收和完整冲突删除/撤销、更多复杂数据库类型、用户安装升级与真实迁移回退尚未全部验证。P7 的候选版门保持打开，直到 `PLAN.md` 列出的功能、兼容、桌面和最终性能项目均有对应证据。
