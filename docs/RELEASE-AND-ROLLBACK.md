# GPUI 候选版安装、切换与回退

本文面向候选版验收。2026-11-06 起，用户决定两版**共用一套数据后端**：GPUI 的默认库就是旧版的 `%APPDATA%\Quire\quire.db`，不再另存 `%LOCALAPPDATA%\QuireGPUI\`。安装标识仍然分开（独立 AppUserModelID、独立安装目录、独立 exe），卸载只撤程序不动数据。两版不能同时打开同一个数据库写入——GPUI 侧由 `<db>-shm` 独占试开拦下，旧版侧尚无对应检查（旧版代码未改），所以"GPUI 常驻时再开旧版"仍需人工遵守。

## 候选包验收

1. 仅从锁定依赖构建 Release，并记录源码 commit、Rust/Cargo 版本、构建命令、耗时和最终二进制 SHA-256。最终性能比较另按 `PLAN.md` 的 P7 项目执行；功能冻结前记录的单次构建耗时不作为两版结论。
2. 运行全量自动测试、隔离 Release GUI smoke、旧版同库兼容和同步线协议回归。所有测试必须使用新建的 `%TEMP%` fixture 或 `quire-gpui` 仓库下的自动化测试库。
3. 生成便携 ZIP；安装器仅在 Inno Setup 6 编译器可用时构建。将 ZIP 解压到全新临时目录，核对包内 EXE SHA-256 与构建产物一致，再启动并退出。
4. 记录未通过、未覆盖和必须由真实桌面操作验证的项目。人工门（IME、托盘、多屏、DPI、鼠标命中）未通过前，不称为完整验收版。

## 切换前备份

- 先完全退出 Slint 和 GPUI，检查任务管理器确认没有仍在运行的 Quire 进程；不得在两版同时运行时复制或切换同一个库。
- 在旧版中确认当前库路径并使用旧版已有备份功能；另将旧版数据库所在的**整个数据目录**复制到带日期的离线备份位置。保留数据库、SQLite sidecar、附件目录、页面版本与配置文件，不能只复制 `.db`。
- GPUI 的默认库现在就是旧版那颗 `%APPDATA%\Quire\quire.db`，不存在"第一次用空目录评估"这一步。任何兼容检查仍然先在 `%TEMP%` 上做：退出两版，复制整个旧版数据目录，用 `--db` 显式指向副本；`--import-library` 也只在副本上跑通后才对准真实库，绝不对旧版原库直接执行。
- 记录源目录、库文件大小、页面/块/数据库/笔记/任务数量和附件哈希清单；成功打开、保存、关闭并重开后复核这些值。2026-11-06 用户授权把真实库直接作为共用后端，因此这一轮的真实库读数是按"先副本、后真实"两步走的：副本上跑通才对准 `%APPDATA%\Quire\quire.db`。

## 回退

- 共用一套数据后端之后，回退不再是"换回旧库"，而是"退出 GPUI，用旧版打开同一颗库"。旧版原安装保持原样即可；GPUI 写进共用库的行旧版读得出来（副本与真实库两轮都验过：合并后的真实库由本轮新构建的 `quire-slint.exe --dump-state` 读出 `pages=16`）。真出问题要退回合并前的数据形状，只能从切换前的整目录副本恢复，不要指望库内的滚动备份。
- 旧版原有的 `quire.db.bak1..bak5` 是**合并前**的快照，而 GPUI 的损坏恢复会按同名滚动备份并在需要时用最新一份覆盖主库——那正好会把这次合并抹掉。切换时已把这五份改名保留为 `quire.db.bak1..5.premerge-20261106`（2026-11-06 23:13 执行），让两版的备份序列各说各话；旧版随后自己重新生成了新的 `bak1..3`。
- 若要重置共用库，退出两版后从切换前副本恢复整个目录；不要在运行中的库上替换单个数据库文件。GPUI 自己那颗试验库（`%LOCALAPPDATA%\QuireGPUI\`）合并后不要删，留在原地直到用户确认回退窗口结束。
- 卸载 GPUI 不会删除任何数据（数据在共用的 `%APPDATA%\Quire\`），也不应卸载 Slint。卸载后的数据清理需在用户确认后手动进行。

## 当前状态与发布门

已验证 GPUI 的隔离 SQLite 启动备份、活动会话周期快照与损坏恢复、旧版基本/复杂数据库同库往返、v4 同步线协议中的 Number/Formula/Select/Relation/Mirror/Rollup schema、两个方向的同步附件二进制往返、双节点 loopback 上文件列引用移除与恢复，以及便携 ZIP 结构和临时解压启动。共用后端一侧 2026-11-06 新增验证：在 `%TEMP%` 副本上完成旧版库←GPUI 库的一次性合并（页数 8→11、块 289→295、笔记 111→113、任务 15→17，模板行 114-118 未动），合并结果由本轮新构建的旧版 exe 用 `--dump-state` 读出 `pages=16`；GPUI 侧的 `<db>-shm` 独占试开门与默认库路径门均有源码变异自证。周期备份失败会在 UI 明确说明主库保存状态并提供手动重试入口。附件实体回收和完整冲突删除/撤销、更多复杂数据库类型与用户安装升级仍未全部验证；**真实共用后端那一轮已于 2026-11-06 夜间在真实库上执行完毕**（静默备份 → 旧版 bak 家族改名 → 装机版 `--import-library` 真实 GPUI 试验库，pages 8→11 / blocks 289→295 / notes 111→113 / tasks 15→17 → 旧版 `--dump-state` 由 `pages=13` 改报 `pages=16` → GPUI 常驻共用库，`integrity_check` ok、模板行 114-118 未重复），逐条数字与取证过程见 `DIFFERENCES.md`「两版共用一套数据后端与一次性导入」；旧版侧的对称并发写门仍等用户点头，真实的迁移回退（从整目录副本还原）尚未实跑。P7 的候选版门保持打开，直到 `PLAN.md` 列出的功能、兼容、桌面和最终性能项目均有对应证据。
